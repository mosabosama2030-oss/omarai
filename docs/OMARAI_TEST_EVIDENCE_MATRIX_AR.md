## 1. أنواع الدليل

| النوع | ما الذي يثبته؟ | ما الذي لا يثبته؟ |
|---|---|---|
| Unit / deterministic | سلوك دالة/قاعدة محددة في شروط مضبوطة. | اتصال حي أو تكامل خارجي أو أداء إنتاجي. |
| Mock / monkeypatch | تعامل المكون مع استجابة/فشل اصطناعي محدد. | صلاحية مفاتيح أو توافر موفر حقيقي أو مطابقته للسلوك الفعلي. |
| Local HTTP integration | تشغيل Handler/API الفعلي على loopback مع قاعدة اختبار. | صحة TLS أو CORS عبر مضيف حقيقي أو هوية نشر عامة. |
| Container smoke on CI | بناء الحاوية وتشغيلها واختبار مسارات API أساسية محلية ومحمية. | نشر فعلي أو دوام الملفات أو اتصال كل موفر خارجي. |
| Live provider diagnostic | موفر محدد رد في وقت الاختبار من بيئة الاختبار. | استمرار التوافر أو دقة كل إجابة أو استقلال المصادر. |
| Hosted acceptance smoke | مسار مصادق عليه يعمل على عنوان الاستضافة الذي فُحص وقت التشغيل. | توافر مستمر، حمل إنتاجي، استعادة بيانات، أو امتثال أمني شامل. |
| Load / restore / red-team | فقط النطاق المحدد في التقرير ونتائج الاختبار التي نُفذت. | أي نطاق أو تهديد لم يشمله القياس أو الاختبار. |

## 4. ما الذي لا يزال NOT_RUN / UNKNOWN؟

حتى إعداد هذه المصفوفة:

- **NOT_RUN:** لم يُنفذ الاختبار الحي الشامل للموفرين عبر استضافة محددة في هذه الجولة.
- **NOT_RUN:** لم يُنفذ اختبار يدوي بالمتصفح على الخدمة المنشورة.
- **NOT_RUN:** لم يُنفذ اختبار حمل ممثل أو soak test.
- **NOT_RUN:** لم تُثبت استعادة نسخة SQLite على مضيف الاستضافة المستهدف.
- **UNKNOWN:** صلاحية مفاتيح موفري البحث/النموذج وقيود حساباتهم الفعلية، ما لم يثبتها اختبار حي منفصل.
- **UNKNOWN:** ربط SHA الموجود في `main` بالـartifact الفعلي لخدمة عامة، ما لم تتوفر بيانات نشر قابلة للفحص.
- **UNKNOWN:** سلوك الوكيل العكسي الحقيقي وTLS وCORS وإعداد التخزين لكل مضيف بعينه.

## 5. طريقة تشغيل قبول حي — بعد الموافقة فقط

هذا الإجراء ليس جزءًا من اختبارات PR العادية، وقد يستهلك استخدامًا من مزودي النموذج أو البحث.

المتطلبات قبل التشغيل:
1. وجود خدمة Omarai منشورة يملك مدير المشروع صلاحية اختبارها.
2. التحقق من أن الهدف هو أصل HTTPS المقصود.
3. إعداد `OMARAI_BASE_URL` و`OMARAI_ACCESS_TOKEN` في GitHub Secrets فقط، وعدم وضع الرمز في مدخلات workflow أو تعليق أو سجل.
4. موافقة صريحة على إجراء اختبار حي قد يستهلك رصيدًا.
5. استخدام سؤال عام غير حساس، وعدم استخدام بيانات عملاء حقيقية.
6. تسجيل commit/نسخة الخدمة والوقت ونتيجة كل خطوة دون تسجيل أي سر.

يشغّل `scripts/hosted_smoke_test.py`:
- فحص `/api/health`.
- اختبار أن `POST /api/agent` بلا رمز يرجع 401.
- فحصًا حيًا للبحث والنموذج من `/api/diagnostics`.
- سؤالًا عربيًا يتطلب بحثًا ومصادر.
- تحققًا من أن التقرير لا يحتاج إلى كشف مفاتيح.

إذا لم تتوفر البيئة أو الأسرار أو الموافقة على الاستخدام، تبقى النتيجة `NOT_RUN`؛ لا يُستعاض عن ذلك بنجاح CI.

## 6. شروط قبول نتيجة أي اختبار

يجب أن يتضمن سجل النتيجة:
- معرف الاختبار واسمه.
- نوع الاختبار (unit/mock/local/container/live/load/restore/red-team).
- SHA والفرع أو النسخة المنشورة.
- الأمر أو workflow ورابط التشغيل.
- إعدادات البيئة اللازمة دون الأسرار.
- النتيجة الفعلية ووقت الاختبار.
- ما يثبته الاختبار وما لا يثبته.
- الحالات المستثناة أو التي لم تُنفّذ.
- المسؤول عن مراجعة النتيجة ومعايير الإغلاق.

لا تُحوّل `NOT_RUN` إلى `PASS`، ولا تستخدم نجاح Mock دليلًا على توفر موفر حي.
