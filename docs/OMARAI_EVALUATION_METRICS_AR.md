# مجموعة التقييم وقياس الأداء لعمرai

**المعرّف:** OMARAI-EVAL-METRICS-001  
**الإصدار:** 1.0  
**حالة خط الأساس التاريخي:** `NOT_MEASURED` — لا توجد في الأدلة المتاحة نتيجة تشغيل مُراجَعة على SHA المرجعي القديم.  
**المرجع التاريخي المحدد في مجموعة الحالات:** `ac05f4777f140694b285c5364e6c3875fdecdae6`.  
**مبدأ القبول:** لا يُعلن التحسن قبل تشغيل النسختين على الحالات نفسها وتوثيق SHA والنتائج الفعلية. لا تُملأ أرقام الأساس بالتخمين.

## ما الموجود بالفعل وما الذي أُضيف

- مجموعة `OMARAI-REDTEAM-001` الحالية تضم 45 حالة: 14 `ar-EG`، و9 `ar-MSA`، و13 `en`، و9 `mixed`، عبر 20 فئة تقريبًا؛ راجع `tests/fixtures/answer_quality_cases.json`.
- `scripts/run_answer_quality_benchmark.py` يجمع إجابات API لكنه لا يحكم تلقائيًا على صحتها؛ تظل الإجابات `NOT_TESTED` حتى مراجعتها.
- `scripts/evaluate_benchmark_metrics.py` يحسب المقاييس من سجلات تشغيل تمت مراجعتها، ويقارن خط أساس ومرشحًا باستخدام **معرّفات الحالات المشتركة فقط**.
- `tests/test_evaluate_benchmark_metrics.py` يغطي الحسابات، القيم المجهولة، حالات عدم محاولة الأداة، المقارنة المقترنة، وصحة البيانات.

## تعريف المقاييس

| المقياس | التعريف | قاعدة منع التضليل |
|---|---|---|
| الدقة (Accuracy) | الحالات الصحيحة ÷ الحالات التي راجعها مقيّم مستقل | `correct` يجب أن يكون true/false بعد المراجعة؛ `null` غير محسوب |
| استدعاء الادعاءات المرجعية (Claim recall) | الادعاءات الذهبية المسترجعة ÷ إجمالي الادعاءات الذهبية المشروحة | يتطلب ترميزًا مسبقًا لـ `gold_claims` و`retrieved_gold_claims` |
| جودة الاستشهادات (Citation precision) | الاستشهادات المدعومة ÷ الاستشهادات الكلية التي جرى فحصها | وجود رابط لا يعني دعم الادعاء؛ يجب على المراجع فحص كل استشهاد |
| تغطية الاستشهادات | الحالات التي تتطلب مصادر وبها استشهاد واحد على الأقل ÷ حالات طلب المصادر التي عُرفت بياناتها | مقياس منفصل عن صحة الاستشهاد |
| نجاح الأدوات | استدعاءات الأدوات الناجحة ÷ محاولات الأدوات للحالات التي تتطلب أداة | عدم المحاولة الصريح لأداة مطلوبة يُحسب فشلًا؛ المحاولة المجهولة تبقى خارج المقام |
| زمن الاستجابة | الوسيط وP95 للزمن المقاس حول طلب API | لا تخلط زمن API بزمن البحث وحده؛ قارن بيئات متطابقة |
| التكلفة | مجموع ومتوسط التكلفة المرصودة لكل طلب بالدولار | المفقود يظل `null`، لا صفرًا؛ لا يُقدّر السعر دون سجل أسعار/استخدام موثق |
| التغطية | عدد الحالات/الملاحظات المتاحة لكل مقياس | تُعرض بجانب كل نتيجة؛ لا تعتبر نقص القياس نجاحًا |

P95 يستخدم استيفاءً خطيًا لموضع `(n-1) × 0.95`؛ وهذا تعريف حتمي مناسب للعينات الصغيرة. عند نشر مقارنة، أرفق كذلك أعداد الحالات المشمولة بكل مقياس، وليس النسب وحدها.

## صيغة سجل التشغيل المُراجع

أنشئ ملف JSON مستقل لكل تشغيل. لا تضع مفاتيح API أو رموز الوصول أو أجسام أخطاء مزودي الخدمة في الملف.

هذا المثال **شكل توضيحي وليس نتيجة تشغيل حقيقية**. استخدم `null` عندما تكون القيمة غير معروفة. لا تسجل أسماء مراجعين شخصية إذا كان معرّف داخلي كافيًا. حالات البحث يجب أن تحتوي على قائمة الادعاءات الذهبية المعتمدة في ملاحظات المراجعة/ورقة الترميز، ويجب على مراجع مستقل تحديد ما إذا كان كل ادعاء مسترجعًا ومدعومًا.

## التشغيل

### 1. تحقق من ذخيرة الحالات (دون شبكة)

```bash
python scripts/run_answer_quality_benchmark.py --mode validate --summary
python -m pytest tests/test_answer_quality_corpus.py tests/test_answer_quality_runner.py tests/test_evaluate_benchmark_metrics.py -q
```

هذا يتحقق من البنية فقط، ولا ينتج درجة جودة.

### 2. اجمع إجابات نسخة محددة

```bash
python scripts/run_answer_quality_benchmark.py --mode live \
  --base-url http://127.0.0.1:8765 --limit 45 --delay 1 \
  --out artifacts/eval-candidate-<sha>.json
```

يجب أن تكون الخدمة المحلية تعمل بالفعل. للمضيف HTTPS، لا تستخدم رمز وصول إلا بعد تحديد `OMARAI_BENCHMARK_ALLOWED_ORIGIN` لمطابقة الأصل حرفيًا، مع `OMARAI_ACCESS_TOKEN` من بيئة آمنة. لا تضع الأسرار في سطر الأوامر أو ملفات النتائج. التشغيل الحي قد يستهلك ميزانية مزود النموذج/البحث؛ لا تشغله على الاستضافة دون موافقة مسؤول التشغيل.

بعد الجمع، أضف مراجعات `correct`، وترميز الادعاءات الذهبية، وعدّ الاستشهادات المدعومة، وحالة الأدوات، وتكلفة موثقة. لا تسمح للأداة بوضع PASS تلقائيًا اعتمادًا على تشابه الكلمات.

### 3. قارن خط الأساس بالنسخة المرشحة

```bash
python scripts/evaluate_benchmark_metrics.py \
  --baseline artifacts/eval-baseline-<sha>.json \
  --candidate artifacts/eval-candidate-<sha>.json \
  --out artifacts/eval-comparison.md \
  --json-out artifacts/eval-comparison.json
```

ترفض الأداة اختلاف معرف/إصدار مجموعة الاختبار، وتستخدم الحالات المشتركة فقط، وتصدر قيمًا `N/A` عند غياب البيانات. يجب تشغيل نفس الأسئلة وبنفس إعدادات البيئة والمراجعة؛ وعند مقارنة جودة البحث الحي، سجّل أن تغير الويب أو المزود قد يؤثر في النتيجة.

## بروتوكول خط الأساس

1. خط الأساس المقترح تاريخيًا هو commit `ac05f4777f140694b285c5364e6c3875fdecdae6` المشار إليه في ملف الحالات؛ لا يُعد ذلك قياسًا بحد ذاته.
2. شغّل الاختبارات الـ45 على نسخة الأساس وعلى المرشح، مع تسجيل SHA الفعلي لكل منهما.
3. طبّق معيار مراجعة واحدًا، ويفضل مقيّمين مستقلين للحالات الدلالية عالية المخاطر، وسجّل خلافاتهما.
4. قارن النتائج المقترنة على `case_id` نفسها. اذكر حجم العينة والتغطية وأي حالات فاشلة/مفقودة.
5. لا تدمج أو تنشر بناءً على متوسط أعلى وحده؛ راجع تراجع الأمان، الحالات الحرجة، الاستشهادات غير المدعومة، وفشل الأدوات.
6. خزّن JSON الخام المنقح، ورقة الترميز، التقرير Markdown، SHA، وتاريخ التشغيل في `artifacts/` أو سجل معتمد دون أسرار.

## الحالة الفعلية عند إنشاء هذا الملف

- **VERIFIED:** الذخيرة الموجودة تحتوي 45 حالة متعددة اللغات؛ runner الحالي يجمع الردود الحية لكنه لا يصنّف الجودة آليًا.
- **IMPLEMENTED IN THIS CHANGE:** مجمّع مقاييس مستقل ومقارنة baseline/candidate مقترنة، مع اختبارات حسابية.
- **NOT_RUN:** لم تُنفذ الخدمة الحية أو مراجعة بشرية على أي من نسختي baseline/candidate في هذه المهمة.
- **NOT_MEASURED:** لا توجد أرقام فعلية موثقة للدقة/الاستدعاء/جودة الاستشهادات/نجاح الأدوات/الزمن/التكلفة على SHA التاريخي المرجعي؛ لذلك لا يمكن الادعاء بأن معيار المقارنة النهائي قد اجتاز.
- **BLOCKER:** يلزم تشغيل نسخة `ac05f477...` ونسخة المرشح في بيئة يمكن تشغيلها، ثم إدخال نتائج فعلية ومراجعتها. لا يمكن استنتاج هذه الأرقام من نجاح CI أو من وجود الذخيرة وحده.

## بوابة القبول النهائية

يُقبل الإصدار فقط عند توفر: (1) نتائج baseline وcandidate على الحالات نفسها، (2) SHA كامل لكل تشغيل، (3) مراجعة جودة موثقة، (4) قيم المقاييس وتغطيتها، (5) نتائج P50/P95 والتكلفة من بيانات حقيقية، (6) تقرير فروق قابل لإعادة الإنتاج، و(7) عدم وجود تراجع أمني حرج. قبل ذلك الحالة `PARTIAL` لا `VERIFIED`.
