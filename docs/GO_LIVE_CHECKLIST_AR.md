# قائمة قبول Omarai قبل اعتبار النشر ناجحًا

وجود Dockerfile أو اكتمال GitHub Actions لا يعني أن خدمة عامة أُنشئت. لا نعلن اكتمال النشر إلا بعد فتح عنوان HTTPS الحقيقي واجتياز اختبارات التشغيل الحي.

## إعداد الاستضافة

1. اتبع [دليل SnapDeploy العربي](DEPLOY_SNAPDEPLOY_AR.md) لإنشاء حسابك وربط المستودع `mosabosama2030-oss/omarai` والفرع `main`.
2. اقرأ صلاحيات GitHub التي يطلبها مزود الاستضافة قبل الموافقة عليها. لا توافق على نطاق وصول لا تقبله.
3. انشر من Dockerfile الموجود في جذر المستودع. لا تتجاوز أي خطوة تعرض شراء خطة أو إضافة مدفوعة.
4. اضبط في لوحة الاستضافة السرية فقط:
   - `OMARAI_PUBLIC_DEPLOYMENT=1`
   - `OMARAI_ACCESS_TOKEN`: رمز عشوائي مستقل قوي لا يقل عن 32 حرفًا.
   - `OPENROUTER_API_KEY`: مفتاح المزود الشخصي المستخدم للنماذج.
5. اترك `OMARAI_OPENROUTER_WEB_SEARCH` ومفاتيح البحث الإضافية غير مضبوطة ما لم تتم مراجعة التكلفة والموافقة عليها.
6. انسخ نطاق HTTPS الذي أنشأته المنصة وافتح `/api/health`. يجب أن يعيد HTTP 200. لا تنشر الأسرار في GitHub أو المحادثات أو السجلات.

## اختبارات قبول إلزامية يدويًا

- افتح الصفحة الرئيسية من متصفح الهاتف.
- أدخل رمز `OMARAI_ACCESS_TOKEN` في خانة الوصول داخل الواجهة، وليس مفتاح OpenRouter.
- اضغط اختبار الإنترنت والنموذج وتأكد من ظهور نتائج واقعية لكل منهما.
- اسأل سؤالًا عربيًا حديثًا؛ افتح المصادر وتحقق أنها ذات صلة وتدعم الادعاءات الأساسية.
- اسأل سؤال متابعة لاختبار استمرار السياق.
- جرّب طلب API بلا رمز أو برمز خاطئ، وتأكد من رفضه (يفترض أن يعيد `POST /api/agent` غير المصرح به HTTP 401).
- اختبر الرابط من نافذة خاصة أو متصفح آخر، وتأكد أن الواجهة لا تكشف مفاتيح أو تسمح باستعمال الـ API دون مصادقة.

## اختبار القبول الآلي الاختياري

الاختبار الحي يرسل طلبات حقيقية للبحث والنموذج وقد يستهلك استخدامًا من حساب المزود. شغّله فقط بعد الموافقة على ذلك:

1. من GitHub افتح **Settings → Secrets and variables → Actions**.
2. أضف `OMARAI_ACCESS_TOKEN` بقيمة الرمز نفسها المهيأة في الاستضافة.
3. أضف `OMARAI_BASE_URL` بقيمة أصل HTTPS فقط، دون `/api/health` أو مسار أو query؛ مثال: `https://اسم-الخدمة.containers.snapdeploy.app`.
4. افتح **Actions → Omarai hosted acceptance smoke → Run workflow**.
5. تحقق من نجاح الفحص الصحي، رفض الطلب غير المصرح به، وتشخيص البحث والنموذج والإجابة العربية. لا تشارك الأسرار في تقرير الاختبار.

## حدود النسخة الحالية

- الخطة المجانية في SnapDeploy تنام بعد عدم النشاط، وحد ساعاتها شهري ومشترك على مستوى الحساب؛ ليست ضمان تشغيل 24/7. راجع [الحدود الحالية](https://snapdeploy.dev/docs/free-tier).
- قاعدة SQLite محلية على الحاوية وقد لا تبقى بعد إعادة النشر أو استبدال الحاوية. لا تحفظ بيانات عملاء أو بيانات شخصية مهمة قبل إعداد قاعدة بيانات دائمة ونسخ احتياطي.
- محدد الطلبات الحالي موجود في ذاكرة العملية، وليس نظام تحديد معدل موزعًا لعدة نسخ.
- يعتمد التوليد على مزود نموذج خارجي؛ قد تختلف الإتاحة والسرعة والحدود والتكلفة. لا ترسل إليه بيانات سرية.
- لا تساوِ بين نجاح البناء، وظهور صفحة، ونجاح الوكيل. يجب أن ينجح البحث والنموذج والإجابة العربية والمصادر من عنوان الاستضافة الحقيقي.
