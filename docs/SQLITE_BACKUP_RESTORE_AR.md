# Omarai — النسخ الاحتياطي والاستعادة لقاعدة SQLite

## الغرض والنطاق

يوفر `scripts/sqlite_backup_restore.py` أمرًا محليًا لإنشاء نسخة SQLite متسقة لقاعدة Omarai التي تحتوي جدول `leads`، ثم استعادتها إلى **مسار جديد غير موجود**. يستخدم الأداة القياسية `sqlite3.Connection.backup` ويتحقق من `PRAGMA integrity_check` وعدد السجلات. لا يغيّر هذا التغيير قاعدة `LeadStore` ولا يضيف جدولة نسخ احتياطية تلقائية.

هذا يثبت إمكانية النسخ والاستعادة ضمن الاختبارات المحلية؛ لا يثبت أن نظام الملفات في مضيف استضافة معين دائم أو أن النسخ خارج المضيف تلقائيًا.

## الأمان والسلوك الافتراضي

- لا يستبدل الأداة أي ملف موجود. يجب اختيار وجهة جديدة؛ إذا كانت موجودة يفشل الأمر بدل الكتابة فوقها.
- يتحقق من أن المصدر قاعدة SQLite سليمة تحتوي جدول `leads`.
- يرفض أن يكون مسار المصدر والوجهة متطابقين.
- ينشئ ملف الوجهة بصلاحيات مقيدة قدر الإمكان (`0600` على أنظمة POSIX).
- يحذف ملف الوجهة الجزئي الذي أنشأه إذا فشلت عملية النسخ/الاستعادة.
- لا يعدل المصدر.
- لا يشفر النسخة الاحتياطية ولا ينقلها إلى موقع خارجي. النسخة تحتوي بيانات العملاء نفسها؛ احمِ الملف، ولا ترفعه لمستودع عام أو خدمة غير مصرح بها.
- لا يوجد خيار overwrite. للاستعادة المقصودة إلى مسار يستخدمه التطبيق، يجب إيقاف التطبيق أولًا، واتخاذ نسخة إضافية، ومراجعة المسار والإجراء يدويًا؛ هذه الوثيقة لا تمنح تفويضًا باستبدال قاعدة إنتاج.

## أوامر الاستخدام

من جذر المستودع، مع اختيار مسارات جديدة:

```bash
python scripts/sqlite_backup_restore.py backup ~/.omarai/omarai.sqlite3 ./backups/omarai-2026-10-19.sqlite3
```

يجب أن يكون مسار الوجهة غير موجود. إذا نجح الأمر، يعرض JSON به نتيجة التحقق وعدد سجلات `leads`، دون إظهار محتوياتها.

لاستعادة النسخة إلى قاعدة اختبار جديدة:

```bash
python scripts/sqlite_backup_restore.py restore ./backups/omarai-2026-10-19.sqlite3 ./restore-test/omarai.sqlite3
```

يعيد الأمر التحقق من سلامة قاعدة البيانات وعدد السجلات. بعد الاستعادة، يمكن فحصها باستخدام Omarai في بيئة اختبار فقط، على سبيل المثال عبر `LeadStore` أو اختبار آلي. لا توجّه الاستعادة إلى قاعدة البيانات المستخدمة حاليًا.

## الاختبارات

```bash
python -m pytest -q tests/test_sqlite_backup_restore.py
```

تغطي الاختبارات:
- حفظ نسخة واستعادتها إلى ملف جديد ومقارنة السجلات والحقول.
- رفض الكتابة فوق وجهة موجودة.
- رفض SQLite غير التابعة إلى Omarai.
- رفض تطابق المصدر والوجهة.
- رفض ملف نسخ تالف دون إنشاء وجهة أو تغيير المصدر.

يجب مراجعة نتيجة CI على SHA الخاص بالتغيير قبل اعتماد التنفيذ.

## حدود الاستعادة التشغيلية

اختبار الاستعادة المحلي لا يكفي لقبول قاعدة إنتاج. قبل الاعتماد على بيانات لا يمكن تعويضها، اختبر على المضيف المحدد:

1. أن ملف قاعدة البيانات موجود في تخزين دائم وفق وثائق المضيف.
2. أن النسخة الاحتياطية يمكن حفظها خارج دورة حياة الحاوية، في مكان مصرح به.
3. أن عملية الاستعادة جُربت بعد إعادة إنشاء بيئة اختبار جديدة.
4. أن عدد السجلات والحقول والتتبّع متطابق بعد الاستعادة.
5. أن زمن الاستعادة وفقد البيانات المحتمل موثقان، أو يبقيان `UNKNOWN`.
6. أن سياسة الاحتفاظ والحذف وحماية النسخ الاحتياطية واضحة.

لا يوجد في هذا التغيير اختبار حي لمضيف استضافة، ولا جدولة تلقائية، ولا تشفير للنسخ، ولا هدف RPO/RTO مُقاس.
