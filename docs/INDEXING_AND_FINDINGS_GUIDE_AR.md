# دليل فهرسة Omarai وسجل الهفوات

**المعرف:** OMARAI-INDEX-GUIDE-001  
**الحالة:** طريقة تشغيل ومراجعة؛ لا تعني اكتمال الفهرسة قبل نجاح الفحص على النسخة الحالية.

## 1. أين أبدأ؟

- `docs/MASTER_INDEX.md`: جرد الملفات وتعريفات Python ورموز واجهة الويب والإعدادات والعناوين.
- `docs/SOURCE_LINES_INDEX.md`: دليل إلى صفحات الأسطر.
- `docs/source_index/SOURCE_LINES_*.md`: أسطر الملفات النصية المؤهلة، مع معرف ثابت للسطر ورابط إلى موضع المصدر.
- `docs/search_code.py`: بحث نصي محلي يعمل من دون API أو خدمة خارجية، ويعرض اسم الملف ورقم السطر والرابط.
- `docs/OMARAI_REQUIREMENTS_REGISTER.md`: سجل المتطلبات؛ يجب ربط نتيجة التدقيق بمعرف متطلب مناسب عندما ينطبق.

الفهرس وسيلة ملاحة، وليس بديلًا لقراءة الملف الفعلي أو الاختبار. قد تتغير أرقام الأسطر عند التعديل؛ أعد التوليد والفحص بعد كل تغيير مؤثر.

## 2. البحث من الكمبيوتر أو Termux

من جذر المستودع:

```bash
python docs/search_code.py "Handler._allowed_origins"
python docs/search_code.py "X-Forwarded-Host" --context 2
python docs/search_code.py --regex "OMARAI_[A-Z_]+" --ext py
python docs/generate_index.py
python docs/generate_index.py --check
```

لا يحتاج البحث النصي إلى مفتاح نموذج أو اتصال بالإنترنت. يتطلب تشغيل الأوامر وجود Python، ويفضل Python 3.11 أو 3.12 لمطابقة مصفوفة CI.

## 3. كيف نسجل الهفوات المعروفة؟

إذا رُصدت مشكلة قابلة للتتبع، اكتب وسمًا واضحًا في تعليق قريب من موضعها، مثل:

```python
# TODO: DOC-INDEX-001 — توثيق الحالة المتبقية وخطوة إغلاقها.
# FIXME: SEC-001 — وصف قصير للمشكلة المثبتة والاختبار المطلوب.
# REVIEW: EVD-001 — مراجعة دليل الاستشهاد قبل اعتماد هذا المسار.
```

تدعم أداة الفهرسة وسومًا صريحة مثل `TODO`, `FIXME`, `BUG`, `HACK`, `XXX`, `REVIEW`, `SECURITY`, و`DEPRECATED` عندما يتبع الوسم وصف. تنشئ الأداة معرف `FND-...` ورابطًا للسطر، وتعرضه في الفهرس الرئيسي. استخدم معرف متطلب موجودًا مثل `SEC-002` أو `API-001` عند انطباقه؛ لا تنشئ معرفًا متعارضًا ولا تعِد استخدام معرف ملغى.

لا تضف وسمًا لمجرد التخمين. صنّف النتيجة `VERIFIED`, `INFERRED`, `PROPOSED`, أو `UNKNOWN`، وحدد الشدة والملف/السطر والأثر والاختبار والقيود في تقرير المراجعة. الوسوم لا تُكتشف إلا إذا كُتبت؛ غيابها لا يثبت غياب العيوب، والفهرسة لا تكتشف كل أخطاء المنطق تلقائيًا.

## 4. ما الذي يدخل الفهرس وما حدوده؟

الجرد يشمل ملفات المستودع التي يستطيع المولد قراءتها، مع حدود حجم، واستثناء للمجلدات المولدة والملفات الثنائية وقواعد البيانات وامتدادات المفاتيح وملفات الاعتماد الحساسة المعروفة. صفحات الأسطر تتضمن المحتوى المؤهل فقط، وليس الملفات التي استُثنيت أو تجاوزت الحد. هذه القائمة الوقائية ليست ماسح أسرار شاملًا؛ لا تضف أسرارًا إلى المستودع أصلًا، وشغّل فحص الأسرار المناسب قبل النشر.

تستخدم بعض لغات الواجهة قواعد ساكنة تقريبية، وليست محللات كاملة؛ لذلك قد تُفوّت رموزًا أو تُدرج تطابقات ليست تعريفات. أسطر المصدر وروابط GitHub أدوات للوصول، وليست ضمانًا أن وصفًا أو متطلبًا صحيح.

## 5. سياسة التحديث والموافقة

- لا تعدّل الملفات المولدة يدويًا؛ عدّل المصدر/المولد ثم أعد التوليد.
- يجب أن ينجح `python docs/generate_index.py --check` بعد التوليد.
- تغييرات فروع المراجعة يمكن أن تحدّث ناتج الفهرس داخل فرعها فقط.
- إذا احتاج `main` إلى تحديث، ينشئ workflow فرعًا وPull Request عاديًا. لا يُسمح بدفع مباشر تلقائي إلى `main` أو دمج آلي.
- لا يُقال إن الفهرس شامل إلا ضمن الملفات والأنواع والحدود المذكورة؛ سجّل `UNKNOWN` لما لم يُفحص.
