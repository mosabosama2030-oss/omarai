# نشر Omarai على SnapDeploy المجاني — دليل عربي

هذا دليل بديل عندما لا يعمل Render. يستخدم Dockerfile الموجود في جذر مستودع Omarai والفرع `main`. **لا يعني وجود الدليل أن الخدمة أُنشئت أو نُشرت بالفعل.**

> **مهم قبل ربط GitHub:** وفق وثائق SnapDeploy الحالية، يطلب تكامل GitHub نطاق OAuth باسم `repo`، ويتيح هذا النطاق الوصول إلى المستودعات الخاصة والعامة كلها على الحساب، وليس مستودع Omarai وحده. راجع شاشة الصلاحيات بعناية. لا توافق إذا كانت الصلاحيات أوسع مما تقبل؛ لا ترسل كلمة المرور أو رمز GitHub لأي شخص.

## 1. حدود الخطة المجانية

بحسب وثائق SnapDeploy التي تمت مراجعتها في 16 أكتوبر 2026:
- لا تحتاج الخطة المجانية إلى بطاقة دفع، ولا توجد مدة تجريبية تنتهي.
- الحد الأقصى 4 حاويات للحساب، مع 100 ساعة تشغيل إجمالية شهريًا لكل الحساب.
- الحاوية الصغيرة تحصل على 512 MB RAM و0.25 vCPU، مع حد 10 عمليات نشر يوميًا (وبحد 5 خلال 12 ساعة).
- تنام الخدمة بعد نحو 15 دقيقة دون زيارات، وقد يستغرق إيقاظها من المتصفح نحو دقيقة.
- لا يوجد تخزين ملفات دائم؛ أي بيانات SQLite محلية قد تضيع عند الإيقاظ أو إعادة التشغيل أو إعادة النشر.
- لا تشترِ Always-On أو Sprint Pack أو قاعدة بيانات مدفوعة لهذا الاختبار. خدمة النموذج الخارجية لها حدود/تكلفة مستقلة عن الاستضافة.

المراجع الرسمية:
- [الخطة المجانية وحدودها](https://snapdeploy.dev/docs/free-tier)
- [تكامل GitHub وصلاحياته](https://snapdeploy.dev/docs/github)
- [متغيرات البيئة والأسرار](https://snapdeploy.dev/docs/environment-variables)

## 2. إنشاء الحساب وربط المستودع

1. افتح [SnapDeploy](https://snapdeploy.dev/) من متصفح الهاتف.
2. أنشئ حسابًا بالبريد الإلكتروني أو بالطريقة التي تفضلها. لا تستخدم كلمة مرور GitHub نفسها.
3. من لوحة التحكم، ابدأ عملية **Deploy** واختر نشر مستودع GitHub.
4. قبل الموافقة على شاشة GitHub، راجع نطاق `repo` المذكور أعلاه. إذا لم تقبل وصول SnapDeploy إلى كل مستودعات الحساب، توقّف ولا تمنحه الإذن.
5. إذا وافقت بعد المراجعة، اختر المستودع `mosabosama2030-oss/omarai`، والفرع `main`.
6. اترك **Root directory** فارغًا لأن `Dockerfile` موجود في جذر المستودع.
7. اختر استخدام `Dockerfile` الحالي، لا تُنشئ Dockerfile بديلًا ولا تستبدل أمر التشغيل. يستخدم Dockerfile متغير `PORT` الذي توفره المنصة.
8. تحقق من أن اسم الحاوية/الرابط لا يحتوي بيانات شخصية. لا تضف نطاقًا مخصصًا مدفوعًا.

## 3. إعداد الأسرار — دون وضعها في GitHub

أضف المتغيرات التالية في شاشة متغيرات البيئة الآمنة أثناء النشر. إذا لم تظهر الشاشة وقت الإنشاء، أضفها من **Container Settings → Environment Variables**:

| المتغير | القيمة |
|---|---|
| `OMARAI_PUBLIC_DEPLOYMENT` | `1` |
| `OMARAI_ACCESS_TOKEN` | رمز مستقل عشوائي بطول 32 حرفًا على الأقل |
| `OPENROUTER_API_KEY` | مفتاح OpenRouter الخاص بك |

لتوليد رمز وصول جديد في Termux، شغّل هذا الأمر محليًا؛ لا ترسل ناتجه في المحادثة ولا تحفظه في ملفات المستودع:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

قواعد مهمة:
- لا تستخدم مفتاح OpenRouter نفسه رمزًا لدخول Omarai.
- أدخل المفتاحين في لوحة الاستضافة فقط، ولا تضعهما في README أو Issues أو ملفات Git.
- اترك `OMARAI_OPENROUTER_WEB_SEARCH` غير مضبوط؛ تفعيله قد يضيف تكلفة بحث من مزود النموذج.
- لا يحتاج Omarai إلى مفاتيح Brave أو Tavily أو شبكات التواصل للاختبار الأولي؛ لا تضفها الآن.
- لا توافق على خطة مدفوعة أو أي شراء. أوقف العملية إذا طُلب منك دفع.

## 4. النشر الأول والتحقق

1. اضغط **Deploy** وانتظر بناء الصورة وبدء الحاوية. لا تكرر النشر بسرعة؛ فحتى عمليات النشر الفاشلة قد تحتسب ضمن الحد اليومي.
2. افتح سجل البناء والتشغيل. لا تنشر السجلات للعامة إذا تضمنت معلومات حساسة.
3. انسخ رابط HTTPS الذي تمنحه المنصة، وافتح `<رابط-الخدمة>/api/health` في المتصفح.
4. يجب أن يعيد مسار الصحة استجابة HTTP 200. لا تعتبر ظهور صفحة الخدمة وحده دليلًا على أن البحث والنموذج يعملان.
5. افتح رابط الخدمة من المتصفح. أدخل `OMARAI_ACCESS_TOKEN` في خانة رمز الوصول داخل الواجهة فقط، ثم اختبر سؤالًا عربيًا عامًا مثل: «ما آخر التطورات المعلنة في الطاقة الشمسية، مع المصادر وتواريخ النشر؟».
6. استخدم زر **اختبار حي للإنترنت والنموذج** داخل الواجهة. تأكد أن البحث رجع نتائج وأن النموذج قدّم إجابة عربية ومصادر قابلة للفتح، وليس ردًا ثابتًا أو ناتجًا من الاختبار المحلي.
7. جرّب الوصول إلى API دون رمز؛ يجب أن يُرفض الطلب غير المصرّح به بـ HTTP 401.

## 5. اختبار القبول من GitHub Actions (اختياري)

بعد أن ينجح الاختبار اليدوي:
1. في مستودع GitHub افتح **Settings → Secrets and variables → Actions**.
2. أنشئ secret باسم `OMARAI_ACCESS_TOKEN` وقيمته هي رمز التطبيق نفسه.
3. أنشئ secret باسم `OMARAI_BASE_URL` وقيمته **أصل رابط HTTPS فقط**، مثل `https://your-app.containers.snapdeploy.app`، من دون مسار إضافي أو شرطة مائلة في النهاية.
4. افتح **Actions → Omarai hosted acceptance smoke → Run workflow**.
5. إذا كانت الخدمة نائمة، افتح رابطها يدويًا بالمتصفح أولًا وانتظر إيقاظها ثم شغّل الاختبار. وفق وثائق الخطة المجانية، طلبات البرامج الآلية قد تتلقى صفحة إيقاظ 503 ولا توقظ الخدمة مثل زيارة المتصفح.

هذا الاختبار يرسل طلب بحث ونموذج فعليين، وقد يستهلك من رصيد/حدود مزود النموذج. لا تشغّله قبل مراجعة الحدود والتكلفة.

## 6. شروط إعلان اكتمال النشر

لا تضع علامة «تم» إلا بعد توثيق كل ما يلي:
- رابط HTTPS حي يعمل من هاتفك.
- `/api/health` يعيد HTTP 200.
- API يرفض طلبًا بلا رمز (HTTP 401).
- سؤال عربي جديد ينتج إجابة فعلية، مع مصادر وبحث ويب مؤكدين.
- الاختبار الحي يوضح نجاح البحث والنموذج؛ ولا تظهر المفاتيح في الصفحة أو السجل.
- تم التحقق من حدود الخطة المجانية، وعدم إضافة أي خدمة مدفوعة.

## 7. حدود الاستخدام الآمن

هذه مرحلة عرض وتجربة شخصية، وليست استضافة إنتاج أو خدمة SaaS جاهزة:
- نظام ملفات SnapDeploy المجاني مؤقت؛ لا تعتمد على SQLite لحفظ العملاء أو البيانات المهمة. لا تُدخل بيانات عملاء حقيقية في هذه المرحلة.
- حد الـ100 ساعة شهريًا مشترك على مستوى الحساب. إذا انتهت الساعات قد تتوقف إمكانية تشغيل الحاوية حتى التجديد.
- قد تنام الخدمة بعد فترة خمول، ويكون أول فتح أبطأ.
- نموذج اللغة مزود خارجي؛ قد تُرسل له أسئلتك والسياق ومقتطفات الويب. لا ترسل كلمات مرور أو مفاتيح أو معلومات شخصية/سرية.
- نطاق GitHub OAuth الذي تطلبه المنصة واسع حسب وثائقها. تستطيع مراجعة التطبيقات المصرح بها وإلغاء الوصول لاحقًا من إعدادات GitHub، لكن إلغاء تكامل GitHub يوقف وصول عمليات الدفع التلقائي الجديدة إلى المستودع.
- لا تنشر رابط الخدمة على نطاق واسع قبل التحقق من المصادقة، ولا تعتبر اختبار الصحة وحده دليلًا على نجاح الوكيل.

**الحالة:** الدليل وإعدادات المشروع لا ينشئان حساب SnapDeploy ولا يمنحان الإذن لـGitHub ولا يطلقان خدمة تلقائيًا. هذه الخطوات يجب تنفيذها داخل حسابك ومراجعة الصلاحيات بنفسك.
