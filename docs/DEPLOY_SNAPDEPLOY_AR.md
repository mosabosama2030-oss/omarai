# نشر Omarai على SnapDeploy Free — دليل عربي خطوة بخطوة

هذا الدليل مخصص لنشر نسخة تجريبية من Omarai من مستودع GitHub الحالي، من دون تغيير الكود أو دفع رسوم استضافة. تمت مراجعة حدود SnapDeploy المنشورة في 16 أكتوبر 2026؛ راجع صفحة الخطة نفسها قبل الضغط على أي زر شراء لأن الحدود قد تتغير.

## قبل البدء: حدود المجاني والأمان

الخطة المجانية المنشورة تشمل حاليًا 4 حاويات كحد أقصى، و512 MB ذاكرة للحاوية الصغيرة، و100 ساعة تشغيل شهريًا مشتركة للحساب، و10 عمليات نشر يوميًا (بحد 5 خلال كل 12 ساعة). تنام الحاوية بعد نحو 15 دقيقة من عدم النشاط وتستيقظ عند الزيارة، وقد يستغرق الاستيقاظ قرابة دقيقة. لا تحتاج الخطة المجانية إلى بطاقة بنكية، لكنها **ليست تشغيلًا متواصلًا 24/7** ولا ضمانًا لتوفر دائم. عند استهلاك الساعات المجانية قد يتوقف التشغيل حتى تجددها.

- الأسعار والحدود الرسمية: https://snapdeploy.dev/docs/free-tier
- ربط GitHub الرسمي: https://snapdeploy.dev/docs/github
- دليل النشر الرسمي: https://snapdeploy.dev/docs/deployment

**تنبيه صلاحيات GitHub:** توضح وثائق SnapDeploy أن ربط GitHub قد يطلب صلاحية `repo` لعرض المستودعات واستنساخها وتثبيت webhook للنشر التلقائي. قد تشمل الصلاحية مستودعات خاصة أخرى في الحساب. اقرأ شاشة الأذونات قبل الموافقة، ولا تمنحها إذا كان نطاق الوصول غير مقبول. لا تُدخل كلمة مرور GitHub أو أي Token في محادثة أو ملف داخل المستودع.

## المرحلة 1 — إنشاء حساب وربطه

1. افتح https://snapdeploy.dev من متصفح الهاتف.
2. أنشئ حسابًا أو اختر تسجيل الدخول بحساب GitHub الذي يستطيع الوصول إلى `mosabosama2030-oss/omarai`.
3. راجع شاشة أذونات GitHub بعناية. إذا طلبت صلاحيات أوسع مما تقبله، ألغِ العملية ولا تكمل الربط.
4. من لوحة SnapDeploy اختر إنشاء/نشر حاوية جديدة، ثم اختر الربط بمستودع GitHub.
5. اختر المستودع `mosabosama2030-oss/omarai` والفرع `main`.
6. اترك Root Directory فارغًا أو على جذر المستودع `/`. لا تحدد مجلد `docs` أو `api`.
7. اترك البناء باستخدام Dockerfile. يوجد ملف `Dockerfile` في جذر المستودع، ويستخدم أمر التشغيل والمنفذ الذي يمرره المضيف؛ لا تستبدل أمر التشغيل إلا إذا أظهر سجل البناء خطأ محددًا.
8. سمِّ الحاوية `omarai` إن طُلب اسم، ثم ابدأ النشر المجاني فقط. إذا ظهرت صفحة تطلب شراء أو اشتراكًا أو إضافة مدفوعة، توقف ولا تؤكد الشراء.

## المرحلة 2 — إدخال المتغيرات السرية

افتح Container Settings أو Variables/Environment في SnapDeploy، وأضف المتغيرات التالية كقيم سرية داخل لوحة الاستضافة فقط:

| المتغير | القيمة |
|---|---|
| `OMARAI_PUBLIC_DEPLOYMENT` | `1` |
| `OMARAI_ACCESS_TOKEN` | رمز عشوائي مستقل قوي لا يقل عن 32 حرفًا |
| `OPENROUTER_API_KEY` | مفتاح OpenRouter الخاص بك |

لإنشاء رمز الوصول على Android داخل Termux، شغّل الأمر التالي محليًا وانسخ الناتج مباشرة إلى حقل `OMARAI_ACCESS_TOKEN` في SnapDeploy:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

احتفظ بالرمز في مكان آمن يمكنك الرجوع إليه. لا تستخدم مفتاح OpenRouter كرمز دخول Omarai، ولا تضع أيًا من المفتاحين في GitHub أو هنا في المحادثة.

يتيح مفتاح OpenRouter طبقة التخطيط وصياغة الإجابات. قد تتغير إتاحة النماذج المجانية أو حدودها؛ تحقق من مزود النموذج. اترك `OMARAI_OPENROUTER_WEB_SEARCH` وبقية مفاتيح البحث الإضافية غير مضبوطة في المرحلة الأولى؛ لا تفعّل خدمة إضافية قد تستهلك رصيدًا من دون مراجعة التكلفة والموافقة عليها.

احفظ المتغيرات ثم أعد النشر إذا طلبت لوحة SnapDeploy ذلك. لا يلزم وضع الأسرار داخل Dockerfile أو ملفات المشروع.

## المرحلة 3 — التأكد من أن الحاوية تعمل

1. انتظر حتى يعرض SnapDeploy أن النشر Healthy/Running. إذا فشل البناء، لا تكرر المحاولة كثيرًا لأن المحاولات الفاشلة قد تُحتسب ضمن حد النشر؛ اقرأ سجل الخطأ أولًا.
2. انسخ عنوان HTTPS الذي أنشأته المنصة، مثل `https://اسم-الخدمة.containers.snapdeploy.app`، إلى متصفح الهاتف.
3. افتح `/api/health` بعد العنوان؛ يجب أن يعيد HTTP 200 وبيانات صحة لا تحتوي على مفاتيح API.
4. افتح الصفحة الرئيسية من جديد. أدخل قيمة `OMARAI_ACCESS_TOKEN` في خانة رمز الوصول في الواجهة واحفظها على هذا المتصفح فقط.
5. اضغط زر الاختبار الحي للإنترنت والنموذج. ينبغي أن تظهر نتائج فعلية لا مجرد رسالة نجاح شكلية.
6. جرّب سؤالًا عربيًا حديثًا وعامًا، مثل: «ما آخر تطورات الطاقة الشمسية في مصر؟ اذكر تاريخ المعلومات وضع روابط المصادر». افتح بعض المصادر بنفسك وتأكد من تطابقها مع الإجابة.
7. جرّب سؤال متابعة يعتمد على السؤال السابق، ثم افتح الرابط من نافذة خاصة أو متصفح آخر وتأكد أن الواجهة لا تسمح بطلبات API دون رمز صحيح.

إذا ظهر خطأ، احتفظ برسالة الخطأ وسجل البناء بعد إخفاء أي أسرار، ثم افحص المتغيرات والمنفذ قبل أي إعادة نشر.

## المرحلة 4 — اختبار القبول الآلي الاختياري

المستودع يحتوي على سير عمل GitHub Actions باسم `Omarai hosted acceptance smoke`، ينفّذ طلبات بحث ونموذج فعلية وقد يستهلك استخدامًا من مزود النموذج. شغّله فقط بعد موافقتك على ذلك:

1. افتح مستودع GitHub ثم **Settings → Secrets and variables → Actions**.
2. أضف `OMARAI_ACCESS_TOKEN` بالقيمة نفسها المستخدمة في SnapDeploy.
3. أضف `OMARAI_BASE_URL` بقيمة أصل HTTPS فقط، دون `/api/health` أو أي مسار إضافي؛ مثال: `https://اسم-الخدمة.containers.snapdeploy.app`.
4. افتح **Actions → Omarai hosted acceptance smoke → Run workflow** وانتظر النتيجة.
5. يجب أن ينجح فحص الصحة، وأن تُرفض مطالبة API غير المصرح بها، وأن ينجح تشخيص البحث والنموذج والإجابة العربية. لا تنشر قيم الأسرار في سجل عام أو تعليق.

## حدود مهمة قبل الاستخدام الحقيقي

- النسخة الحالية مناسبة للعرض والاختبار الشخصي المحدود، وليست SaaS عامة جاهزة للتوسع.
- قاعدة SQLite محلية؛ لا تعتبر بيانات صفحة العملاء دائمة على استضافة مؤقتة، ولا تخزن فيها بيانات شخصية أو بيانات عملاء مهمة قبل إعداد قاعدة بيانات دائمة ونسخ احتياطي.
- محدد الطلبات حاليًا في ذاكرة العملية؛ لا يعتبر نظامًا موزعًا عند تعدد النسخ.
- البحث العام قد يُحجب أو يخضع لحدود مؤقتة، كما قد تتغير إتاحة النماذج المجانية. يجب أن يصرّح Omarai بتعذر البحث بدل اختلاق مصادر.
- يرسل Omarai السؤال وسياق المحادثة ومقتطفات الويب المختارة إلى مزود النموذج عند استخدامه. لا تدخل كلمات مرور أو مفاتيح أو بيانات سرية.
- وجود الإعدادات والوثائق أو نجاح بناء Docker لا يثبت وجود خدمة حية. لا نعلن اكتمال النشر إلا بعد اختبار العنوان الحقيقي من المتصفح واجتياز اختبارات القبول.
